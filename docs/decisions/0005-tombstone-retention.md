# ADR-0005：墓碑策略与保留期

- 状态：**提议**（保留期数值需用户确认，问题 Q3）
- 日期：2026-10-12
- 关联：规格 §8.3、§9.5、§9.8；`docs/data-model.md` §7；需求 ⚠GAP-01/05/06

## 背景

规格要求：删除必须通过可同步的墓碑表达（§8.3）、
删除/归档/完成/取消语义不同（§9.5）、
重要状态变化可追溯（§9.8）、
**但完全没有规定任何保留期**。

这是一个真实缺口（⚠GAP-01）：同步与备份被明确分成两件事（§8.3），
但"误删之后多久内还能找回"这个问题没有任何条款回答。
若不定义，就无法评估数据丢失风险，也无法定义验收门槛。

## 决策

| 数据 | 保留期 | 到期动作 |
| --- | --- | --- |
| 软删除对象（用户可见的"回收站"） | **180 天** | 硬删除内容 + 写 `delete` 墓碑 |
| `delete` 墓碑（`entity` 行：id/类型/时间/HLC） | **永久** | 不清理 |
| `op` 操作日志 | **90 天** | 压缩为"每对象最后状态 + 关键事件（create/delete/状态变更/转换）" |
| 已解决的 `conflict` 记录 | **90 天** | 归档到审计表 |
| 孤儿 blob（无任何引用） | **30 天** | 删除文件 |

所有数值**用户可配置**，但默认值不得为 0。

## 理由

### 为什么墓碑必须永久保留

考虑一个具体场景：设备 C 离线 12 个月后上线。

- 若墓碑已被清理：设备 C 推上来的旧 `create`/`set` op 会被服务端接受，
  **已删除的对象在其他所有设备上复活**。用户会看到"删掉的东西自己回来了"。
- 若墓碑保留：设备 C 的 op 被 `delete` 墓碑按总序压制，删除状态正确传播。

成本极低：一条墓碑行约 100 字节（id 字符串 + 类型 + 时间 + HLC）。
一万条删除约 1 MB。相对于"数据自己复活"的信任损失，这个成本可以忽略。

**这也是"删除"与"归档"必须在数据模型层面分开的原因**：
归档只是标志位（内容保留），删除必须留墓碑。

### 为什么软删除对象保留 180 天

- 误删后"过了很久才发现"是常见情况（月度回顾、季度整理）。
- 90 天太短（跨不过一个季度），365 天会让回收站难以浏览。
- 180 天是折中，且用户可配置。

### 为什么 op 日志 90 天后要压缩

op 日志是权威历史，但**全量永久保留会让数据库单调增长**：
按每天 50 次操作估算，一年约 1.8 万行；重度使用（每天 500 次）十年约 180 万行，
加上字段级版本向量，会明显影响备份体积与迁移耗时。

压缩保留的内容（保证"重要状态变化可追溯"仍成立）：
- 每个对象的 `create` op；
- 每个对象的最后状态（合成一条 `set` op）；
- `delete` / `restore` op；
- 状态变更类字段的历史（task.status、inbox.status、reminder.status）；
- 转换关系（`conversion_refs` 的 set_add）。

丢弃的内容：中间过程性的普通字段修改。
**规格 §9.8 只要求"重要状态变化"可追溯，不要求所有中间态。**

### 为什么孤儿 blob 30 天

- 用户可能"先删引用，再决定重新加回来"。
- 30 天足够覆盖误操作；同时避免磁盘无限增长。

## 后果

- **正面**：数据丢失风险可量化；误删可恢复；旧设备复活不会造成"数据回来"。
- **负面**：
  - 回收站需要 UI（否则 180 天保留期对用户不可见等于没有）。
  - 压缩任务本身需要测试（压缩后"最后状态"必须与压缩前一致——
    这是新增的**一致性风险**，必须用测试守护，见 T-OPLOG-COMPACT）。
  - 墓碑行永久存在，意味着"完全删除某对象的所有痕迹"**不可能**。
    这对隐私是**有意**的取舍：审计与同步正确性优先。
    但仍需在文档中明确：**硬删除后 id 与时间仍保留在墓碑中**
    （内容已清除，不含任何正文）。若要"彻底抹除"，需要额外提供
    "重建数据库"式的导出/导入（会破坏与其他设备的同步关系）——V1 不做。
- **必须新增的测试**：
  - T-OPLOG-COMPACT：压缩后每个对象的当前状态与压缩前全等；
  - T-RETENTION-TOMBSTONE：模拟离线设备上传旧 op，删除状态不被复活；
  - T-RETENTION-PURGE：软删除到期后内容被清空（正文不再出现在库中任何位置）。

## 开放项（问题 Q3）

用户需确认：墓碑永久保留是否接受（隐私取舍）、180/90/30 天是否符合预期。
