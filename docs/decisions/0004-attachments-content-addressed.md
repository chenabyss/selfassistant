# ADR-0004：附件采用内容寻址存储，且与外部链接分成两个实体

- 状态：**已决定**
- 日期：2026-10-12
- 关联：规格 §4.9、§8.4；`docs/data-model.md` §2.8；需求 ⚠GAP-04/21

## 背景

规格 §4.9 把对象命名为 `Attachment / ExternalReference`，`kind` 取值为
`url` / `file` / `image`，即**一个实体承担两种语义**：

- **外部引用**：只是一个 URL，没有本体，不占空间，不参与备份的"附件"部分。
- **本地文件附件**：有二进制本体，需要存储、校验和、备份、跨设备传输、丢失检测。

而规格同时要求：`checksum` 仅对文件可选、"备份时必须说明附件是否包含在内"、
"文件移动或丢失时应显示失效状态"——这些都只适用于后者。

## 决策

**拆成两个实体与两张元数据表**：

1. `attachment_meta` + `blob`：本地文件，**内容寻址**（sha256 为主键）。
2. `external_ref_meta`：只有 URL、标题、上次可访问性。

引用关系统一走 `set_element(entity_id, field='attachments'|'external_refs', element=<id>)`。

### 内容寻址的具体形态

```
<appData>/blobs/<sha256前2位>/<sha256>      # 无扩展名，媒体类型存数据库
```

- 导入时**复制字节**进上述目录（读取用户文件 → 计算 sha256 → 若已存在则跳过写入）。
- 数据库存 `sha256`、`bytes`、`display_name`、`media_type`、`state`。
- **绝不**依赖用户原始路径或 URI。

## 理由

### 为什么拆成两个实体

一个实体的两条规则集无法同时满足，具体冲突：

| 规格要求 | 对 URL 适用吗 | 对本地文件适用吗 |
| --- | --- | --- |
| `checksum` 校验 | ❌ 无意义 | ✅ 必需 |
| 备份包含附件 | ❌ 不需要（只是个字符串） | ✅ 需要 |
| 文件丢失显示失效 | ⚠️ 是"链接失效"不是"文件丢失" | ✅ |
| 参与 blob 同步 | ❌ | ✅ |
| 有字节数上限 | ❌ | ✅ |

硬塞进一个实体，会导致"备份是否包含 URL"这类无意义的问题，
以及 `state`/`checksum`/`bytes` 字段对 URL 行永远为 NULL 的脏数据。

### 为什么内容寻址

一次决策同时获得四个性质：

1. **天然去重**：同一图片被引用 10 次只占一份空间（原型测试 20 验证）。
2. **天然幂等**：同步上传/下载按 sha256，重传无副作用。
3. **完整性可校验**：备份与同步都能逐文件验证哈希（`backup-restore.md` §3）。
4. **引用共享安全**：删除引用不删本体（§4.9 要求），孤儿清理基于全表引用扫描。

### 为什么"导入即复制"而不是引用原路径

- **Android**：`file_picker` 在 Android 10+ **没有** SAF 持久化 URI 授权
  （上游未决请求 #1825），因此"用户选过的文件以后一直可访问"**不成立**。
- **Windows**：用户会移动/重命名/删除文件；网络盘与可移动盘会离线。
- **跨设备同步**：路径在设备间无意义，只有内容哈希有意义。

代价是导入时占双份空间（直到用户删原文件）。以"单文件 ≤50 MB、单对象 ≤20 个引用"
的上限控制风险（需求 ⚠GAP-21）。

### 为什么不把 blob 存进数据库

SQLite 能存 BLOB，但：
- 备份时数据库体积随附件线性增长，`VACUUM INTO` 的 2 倍峰值空间会很快成为问题；
- 大 BLOB 会显著增加 WAL 体积与 `integrity_check` 耗时；
- 无法像文件那样按需下载（跨设备只拉需要的附件）。

因此：**元数据在库里，本体在文件系统里**。

## 后果

- **正面**：去重、幂等、可校验、引用安全、可按需同步、备份可独立选择是否含附件。
- **负面**：
  - 需要孤儿清理任务（保留 30 天，见 `data-model.md` §7）。
  - 数据库与文件系统之间存在"两处真相"，需要一致性检查：
    启动时校验 `blob.state`，发现文件缺失则置 `missing`（**不**删引用）。
  - 移动/复制应用数据目录时**必须**连 `blobs/` 一起复制（否则附件全部失效）。
    文档需明确写出。
- **安全**：sha256 校验可防止"下载到错误内容"；但**不**提供加密或机密性
  （见 Q4 与 `known-limitations.md` L-28）。

## 相关决策

- 备份是否包含附件：**默认包含**；超过 200 MB 提示改用"仅数据库"
  （`backup-restore.md` §2.4）。
- 附件同步：本体不进 op 日志，只同步元数据（`sync-protocol.md` §7）。
