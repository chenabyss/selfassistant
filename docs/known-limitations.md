## 1. 平台硬限制（无法通过实现消除）

### L-01 Windows：未打包 MSIX 时无法取消或枚举通知

- **表现**：`flutter_local_notifications` 在无 package identity 的应用中，
  `cancel()` 不产生任何效果，`getActiveNotifications()` 返回空列表。
- **依据**：插件官方文档的 Windows Limitations 一节。
- **影响**：无法撤回已弹出的提醒，无法在 UI 里列出"当前活跃提醒"。
- **缓解**：`NotificationScheduler.capabilities()` 返回 `canCancel=false`，
  UI 隐藏"撤回"入口，改为提示用户手动清除系统通知。
- **彻底解决**：改为 MSIX 分发（待决问题 Q6）。

### L-02 Windows：应用未运行时没有可靠的定时执行

- **表现**：标准 `flutter build windows` 产物是未打包 Win32 exe，
  Windows App SDK 后台任务要求 MSIX；未打包时唯一路径是 Task Scheduler，
  而那是**独立的计划任务入口**，不是运行中应用的 Dart 回调。
- **影响**：Windows 上的自动备份与提醒唤醒**只在应用运行时**发生。
- **缓解**：启动时检查"距上次备份 > N 天"并提示；可选"退出时自动备份"；可选托盘常驻。
- **不得**声称：Windows 上"即使未打开应用也会自动备份/提醒"。

### L-03 Windows：不支持重复通知

- `periodicallyShow` / `periodicallyShowWithDuration` 会抛 `UnsupportedError`。
- V1 本就不做重复提醒（见 `decisions/0006`），但代码层必须显式禁止调用，避免运行期崩溃。

### L-04 Android：无法保证精确定时投递

- `POST_NOTIFICATIONS`（Android 13+）是运行时权限，可被拒绝。
- 精确闹钟权限（`SCHEDULE_EXACT_ALARM`）**自 Android 14 起默认不授予**，且用户可撤销；
  `USE_EXACT_ALARM` 不需授权但需 Play 审核，不适用于个人应用。
- 用户撤销权限后，**已安排的精确提醒不再触发**。
- **缓解**：提醒状态落库（`notification_state`），失败在 UI 明确显示；
  提供不精确模式的降级路径。

### L-05 Android：强制停止与重启会清除闹钟

- 应用被 force-stop 后已安排的闹钟永不触发；
- 设备重启会清空所有闹钟，必须声明 `RECEIVE_BOOT_COMPLETED` 并在启动时重新安排。
- **否则**："重启后所有提醒静默消失"。

### L-06 Android：OEM 省电策略可静默阻止后台任务

- 小米（MIUI）、华为、三星等有未公开的后台/自启限制。
- 缓解只能是引导用户设置（自启、电池"无限制"、应用锁定）。
- 三星实现下 `AlarmManager` 有约 500 个待安排上限。

### L-07 Android：`WorkManager` 不能用于准点提醒

- `frequency` 是最小值而非承诺；Doze 批处理可能把"每小时"折叠为"整夜一次"；
  周期任务下限约 15 分钟。
- 可用于周期备份，**不可**用于提醒。

### L-08 Android：16 KB 页面对齐要求

- Google Play 要求 64 位设备上未压缩共享库按 16 KB 对齐（Android 15+ 支持 16 KB 页）。
- 上游 `package:sqlite3` 声称已满足，但**必须在实际构建产物上实测**，不能只信声明。

### L-09 附件：不能依赖用户选定路径长期可访问

- `file_picker` 在 Android 10+ **没有** SAF 持久化 URI 授权。
- 方案强制为"导入即复制"到应用私有目录，数据库只存相对路径 + sha256。
- 代价：大文件占双份空间（导入时）。
